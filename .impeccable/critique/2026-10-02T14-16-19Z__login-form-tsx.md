After HMR or route change back to /login, Alex could see the checkbox on and an empty username field, then submit and overwrite the stored identity. **Fix:** drive reset({ usernameOrEmail: remembered, password: '' }) in the pre-check useEffect. **Suggested command:** `$impeccable polish`
- [P1] Submit button focus ring (focus-visible:ring-neutral-900) is the same color as the button background — focus is invisible. Alex tabbing from password to submit cannot see focus. **Fix:** invert the ring to focus-visible:ring-white with focus-visible:ring-offset-2 focus-visible:ring-offset-neutral-900. **Suggested command:** `$impeccable polish`

Set useForm({ mode: 'onSubmit' }). **Suggested command:** `$impeccable harden`

## Persona Red Flags
Alex (Power User / till staff):
- Submit focus ring is the same color as the button — Alex cannot see focus when tabbing to submit, increasing mis-hits on a till touchscreen.
- Remember-till checkbox can read 'on' while the username input is blank after a remount. Alex submits with no identifier or overwrites the stored identity.
- The 'Hoặc' partner-registration CTA competes for attention on a surface whose explicit purpose is fast till login.

Sam (Screen reader / low vision):
- Two role='alert' elements + RHF per-keystroke revalidation creates overlapping announcements on a single failed submit.
- DOM order has the right-pane <aside aria-label> before the form's <h1>, so the page's first announced heading is decorative.
- Eye-toggle's accessible name lacks the field relationship — Sam won't know it acts on the password input without backtracking.

Riley (Edge case / stress tester):
- Pasting a password with Caps Lock on may bypass the hint because it only updates on the next keydown.
- LocalStorage write is silent — no toast if remember-till storage fails (private mode on a shared iPad).
- Touch target for eye toggle is 28px — mis-tap on tablet.
- Remember-till on a shared till: previous staff's username persists without a clear 'switch user' affordance.

## Minor Observations
- Caps-Lock blur listener fires when focus leaves the document; the hint will go away even when the user is still typing in the password field. Use focusout on the password input instead.
- Remember-till effect could just inspect defaultValues.usernameOrEmail to avoid the second storage hit.
- Border-border/80 on inputs is faint against bg-card in screenshots; on smaller screens the edge nearly disappears.
- Decorative <h2> on right pane uses tracking-[-0.015em] while form's <h1> uses tracking-[-0.02em] — subtle inconsistency.
- Loading state leaves username/password enabled — good — but no spinner at page level; for slow network Alex may think click missed.
- Role chips at bottom look like tabs/badges visually but are <li>s; Sam navigating by list will hear three role announcements back-to-back which is fine but slightly noisy.

## Questions to Consider
- Should the 'Hoặc' divider + partner CTA be removed from operate-mode entirely, or made conditional on a prop so the same component serves both marketing and till contexts?
- Is remember-till persistence meant to span multiple users on a shared till (in which case a 'switch user' affordance is needed) or one staff per device (in which case we should make the social-confusion risk visible)?
- Should the submit focus state invert to white-on-neutral-900, or use a cafe-warm accent ring (amber-300) so the focus is unmistakable?
