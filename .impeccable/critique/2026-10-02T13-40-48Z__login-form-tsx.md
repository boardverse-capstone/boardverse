## What's Working
- Tight information architecture for the till: header → two labeled fields with icons → primary submit → secondary partner action. No distracting marketing, no fake social proof.
- Strong accessibility plumbing: autoFocus on first field, autocomplete hints, aria-invalid wiring, role="alert" for server errors, aria-live, aria-hidden on decorative icons, sr-only figcaption, decorative divider marked aria-hidden.
- Copy and visual treatment match the 'operate' tier: Vietnamese microcopy, no marketing tone, and the right pane communicates 'Realtime · SignalR' and the three roles without becoming a feature carousel.

## Priority Issues
- [P1] Submit button has no visible focus style. Keyboard users tabbing from password → submit get no focus ring because Tailwind reset strips the outline and the className never restores one. Fix: add focus-visible:ring-2 focus-visible:ring-neutral-900 focus-visible:ring-offset-2 focus-visible:ring-offset-card.
- [P1] Server-error live region is 'polite', not 'assertive'; focus is not returned to the username field after a failed submit, so a screen reader user has to navigate back up to find the error. Fix: switch aria-live to 'assertive' and call setFocus('usernameOrEmail') in onError.
- [P1] Inputs stay disabled while isPending, blocking immediate retry correction. Fix: remove disabled={isPending} from usernameOrEmail and password inputs; only disable the submit button.
- [P1] (from overlay) Real low-contrast 4.3:1 on text within bg-card — fails WCAG AA. Two elements flagged: a <p> and a <span>. Likely the muted-foreground copy and the forgot-password link. Fix: bump muted-foreground token in card surface or scope the muted text to a higher-contrast shade.
- [P2] Forgot-password link styling competes with field labels. Same size and color weight as the label until hover. Fix: reduce to text-[11px] or move below the password block.
- [P2] No show-password affordance, no Caps-Lock hint. Cafe till hardware frequently has Caps Lock on. Fix: eye-icon toggle + onKeyDown getModifierState('CapsLock') warning.
- [P3] Right-pane 'Realtime · SignalR' badge promises infrastructure, not user value. Replace with operational text ('Hệ thống đang hoạt động') and keep the green dot.

## Persona Red Flags
Alex (Power User / till staff):
- After a failed submit, inputs stay disabled until React Query settles; Alex can't correct a typo immediately.
- Forgot-password link styled like a label — Alex may tab past it or hit it accidentally.
- No keyboard shortcut to submit; Enter works but no visible hint for staff used to scanner-key workflows.

Sam (Screen reader / low vision):
- Server-error live region is polite, not assertive; 401 not announced until current utterance finishes.
- Focus not returned to usernameOrEmail after failed submit.
- Submit button has no visible focus ring; keyboard position invisible.
- Inline partner-link Button asChild+Link composition has no accessible name distinguishing it from the primary submit.

Riley (Edge case / stress tester):
- After a 429, the form is stuck with disabled fields and no retry timer or unlock hint.
- No Caps Lock detection.
- No show-password affordance.
- The 'Realtime · SignalR' badge lies under simulated offline conditions; nothing reflects connectivity state.

## Minor Observations
- Placeholder 'admin@boardverse.com' hints at an admin seed account — helpful in dev, tiny information leak in prod.
- Two focus rings on inputs are identical neutral-900; consistent but heavy against the soft card.
- Partner-link button competes visually with primary submit because both span full form width at equal density.
- The decorative right-pane inner border at 6% black reads as rendering artifact rather than intentional frame.
- No 'Need help?' support contact visible at the till; a till network failure leaves staff with no recovery path beyond Forgot Password.
- Field-level error uses only text-destructive with no icon; pairing with AlertCircle would improve scannability under till-floor glare.
- useEffect dependency intentionally omitted (eslint-disable) for autofocus on mount only; correct.
